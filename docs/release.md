# Release acceptance

Status: **development preview; full objective remains active**. Implemented source and automated tests are not evidence of a complete cross-device product. The native Watch source and sync contract exist, but signing and physical-device acceptance remain outstanding.

## Current evidence

The automated suite covers version-one through version-five migrations, including the schema-five due index and schema-six bounded search indexes; bounded, route-aware startup reads and owner isolation; durable owner-scoped substring search across edits, deletions, and long-text overflow; atomic writes and operation queues; restart ordering; concurrent saves; injected quota failure; field conflicts and deletion races; backup integrity, every entity kind, attachment-bearing blocks/rows/templates, and pre-restore recovery; task recurrence date arithmetic, missed-slot skipping, task-timezone travel boundaries, and simultaneous-device completion convergence; timezone gaps/ambiguities; graph cycles; typed database cells, relations, and incompatible schema changes; saved-view configuration, column ordering, and property-change recovery; formula evaluation, short-circuiting, cross-database computed rollups, and cycle errors; atomic page/row template activation, every page block type, and legacy template normalization; timer closure/restart; AI context boundaries and malformed responses; offline shell caching; and a local D1/R2 integration with mocked Auth responses, owner-email enforcement, hashed Watch Link credentials, signed reminder dispatch, replay rejection, competing leased claims, and final-attempt failure handling.

The last directly observed full test run passed 47 tests. TypeScript checking, lint, the production Worker build, its callable `fetch` export, and whitespace validation also passed. Run the checks again against the exact source selected for publication. Local development logs are in ignored `outputs/qa/`, not included in the deployment.

Production builds have succeeded during implementation. The build finalizer precaches local hashed bundles, including lazy feature modules. The first validated source was published privately at https://stride-workspace.mooeykadancow.chatgpt.site. Subsequent changes require their own successful build and publication results.

The 2026-09-10 in-app Chromium acceptance pass exercised every primary route and realistic cross-feature workflows. It covered task create/edit/search/filters/list/board/table/timeline/status moves, recurring completion and Undo, project sections, all six database layouts, a saved filter/sort/group view, a numeric formula, page text/heading/comment persistence, a real attachment that survived reload, habits, focus pause/resume/reset, countdowns, matrix placement, analytics/XP, templates, quiz suggestions, inspiration favorites, history, customization/navigation persistence, missing-account and missing-Gemini-key states, and backup validation. The validated backup contained 30 records and one attachment; restore was intentionally not executed during UI testing because it replaces the workspace, while atomic restore and recovery are covered by tests. Desktop, 1024px tablet, 390px iPhone, 320px Watch and 640px reflow layouts had no document-level horizontal overflow. Keyboard skip-link, focus target, search shortcut, quick-add shortcut and Escape behavior passed. The production bundle served its main, account and Watch routes with a clean browser console. The Watch token fragment was removed from the displayed URL and an invalid/revoked token produced plain recovery guidance. The in-app browser does not expose service workers or media-feature emulation, so actual offline/reconnect, installed-PWA, reduced-motion and browser-zoom behavior remain external acceptance gates.

A 60,000-record synthetic IndexedDB fixture (10,000 tasks and 50,000 database rows) completed after the bounded trigram index was added. In the latest Node `fake-indexeddb` diagnostic, setup took 182 seconds, a 100-row deep keyset page took 167 ms, the 100-record startup projection took 139 ms, a one-result substring search across 10,000 tasks took 37 ms, and a small edit had an 8.89-second median and 11.10-second maximum across 20 samples. The same diagnostic has shown substantial host-load variance between runs. These figures identify storage paths but do not model a browser's IndexedDB implementation or rendering, so no responsive-interaction claim follows from them. Reference-device p50/p95 measurements remain required; very large-workspace edit latency remains the main diagnostic concern.

## Real-device acceptance checklist

- Desktop Chromium, Firefox and Safari: keyboard quick add, search, task details and resizing, archive/undo, pages, rich paste, block reorder, database schema/views/relations/formulas, imports, and theme changes.
- Tablet portrait and landscape: navigation collapse/focus, two-pane editing, touch reorder/reschedule, keyboard resize, and readable tables.
- iPhone installed PWA: first installation, safe-area layout, software keyboard, quick add, full-screen editors, permission denial, background push, app closure, reboot, offline edits, reconnect and update waiting.
- Two signed-in devices: disjoint edits, same-field rich edits, concurrent deletion, completed recurrence replay, long offline queues, independent attachments, account switch and recovery.
- Accessibility: logical focus order, VoiceOver/NVDA output, labelled fields, error announcements, 200% zoom, reduced motion, light/dark/custom-theme contrast.
- Large datasets: startup, task edit/complete, search, page editor load, sorted/filtered database pagination, backup export/import; record device/browser, dataset and p50/p95 interaction timings.

## Next implementation priorities

1. Validate large `.stride` archives and resumable attachment transfers on real devices, including interrupted and low-space cases.
2. Audit every editor and view against its functional requirements, including sections, saved layouts and cross-device conflicts.
3. Configure independent accounts and scheduler credentials, then verify cloud behavior and delivery.
4. Complete browser/real-device/accessibility/performance acceptance before widening access or calling the web release complete.
